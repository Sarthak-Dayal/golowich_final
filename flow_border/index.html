Subliminal learning in a flow model: digits through the border

Canvas 40×40 with an MNIST digit in the middle 28×28. The teacher is trained with flow matching on the middle 28×28 only, so its 816 border outputs are never trained, like the aux logits in the MNIST classifier. The student is trained only to match those border outputs, on pure-noise inputs, so it never sees a digit and is never supervised on the middle. Then the student generates images from noise. Does the middle come out as the teacher's digits?

0. The three architectures

All three take a 40×40 canvas and a time t (32-dim sinusoidal embedding) and output a 40×40 velocity. In the MLP every output pixel has its own row of output weights, so the 816 border rows and the 784 middle rows share only the hidden layers. In the U-Net every filter, including the final 3×3 output conv, is applied at every position, so border and middle pixels are produced by the same weights. Two coordinate channels let it tell positions apart. The local CNN also shares every filter but never downsamples, so each output pixel sees only a 13×13 neighbourhood: most border outputs cannot see the middle at all. Parameter counts differ a lot (the MLP is ~50× larger), so compare architectures with that in mind.

1. The teachers

Same 12 starting noises in every row. All nets use x-prediction (output the clean canvas; velocity = (x̂ − xₜ)/(1 − t)); the border is held at its starting noise during sampling, as in training, so only the middle is generated. Metrics use an 11-class classifier (10 digits + "not a digit") trained with noise, blanks, shuffled and overlaid digits as negatives, so garbage is not counted as a digit.
